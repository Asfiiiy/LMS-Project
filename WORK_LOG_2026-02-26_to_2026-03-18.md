## 1. Chat & Ticket System

### 1.1 Chat Transfer & Visibility
- **Issue:** Transferring chat from Operation Manager to Admission Manager caused the chat to not appear for Admission Manager.
- **Fix:** Added department-based visibility in `chatController.js`:
  - `getUserConversations` – now includes ticket conversations where the ticket’s department matches the user’s effective department.
  - `getConversationById` – same logic for opening a conversation by ID.
  - `getMergedTicketMessages` – department-based filtering for merged thread view.
- **Files:** `backend/controllers/chatController.js`, `backend/controllers/ticketController.js`
- **Result:** Admission Manager and other department users see transferred chats; multiple transfers and mark-as-complete work as expected.

### 1.2 Messages Dropdown & Unread Behavior
- **Issue:** Closed (resolved) chats still showed “new message” in the Messages dropdown.
- **Fix:**
  - Backend: When a ticket is set to resolved, all messages in that conversation are marked as read; `ticket_updated` payload includes `conversation_id`.
  - Navbar: Listens for `ticket_updated` (status === 'resolved') and refetches unread count.
  - MessageDropdown: On `ticket_updated` (resolved), clears unread for that conversation and refetches the list.
- **Files:** `backend/controllers/ticketController.js`, `app/components/Navbar.tsx`, `app/components/MessageDropdown.tsx`, `app/chat/page.tsx`, `app/components/FloatingChatWindow.tsx`

### 1.3 Floating Ticket Window & Real-Time Updates
- **Issue:** Ticket messages and notifications not updating instantly; ping timeouts.
- **Fix:**
  - Socket.IO: `pingTimeout: 60000`, `pingInterval: 25000` in `backend/socket.js`.
  - Staff replies: emit `ticket_message` to both student room and conversation room.
  - ChatBox: `reconnect` listener re-emits `user_online` and `join_conversation`.
  - FloatingTicketWindow: `visibilitychange` listener refetches when tab becomes visible.
  - Notification helper: guard against null `userId` in `createNotification`.
- **Files:** `backend/socket.js`, `backend/controllers/ticketController.js`, `app/components/ChatBox.tsx`, `app/components/FloatingTicketWindow.tsx`, `backend/utils/notificationHelper.js`

### 1.4 Socket.IO Auth & Security
- **STEP 1 – Socket auth:** JWT from `handshake.auth.token` or `handshake.query.token`; unauthenticated connections rejected.
- **STEP 2 – Access validation:** `join_conversation` checks DB access (student/tutor/admin/assignee/manager/department, OM/Team) before allowing room join.
- **STEP 3 – Single socket context:** `SocketContext` with `SocketProvider`; `ConditionalLayout` wraps dashboard; Navbar, MessageDropdown, FloatingChatProvider, ChatBox, FloatingChatWindow use `useSocket()` instead of creating their own `io()` instances.
- **Files:** `backend/socket.js`, `app/contexts/SocketContext.tsx`, `app/components/ConditionalLayout.tsx`

### 1.5 Message Status (Sent/Delivered/Read)
- Mark-as-read flow for ticket conversations when resolved.
- `ticket_messages_read` and `message_read` events for read receipts.
- Edit and delete message support in chat APIs.
